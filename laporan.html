4. Detailed Findings

Finding #1 — SQL Injection (Authentication Bypass)
CRITICAL
CVSS: 9.8 — CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
CWE: CWE-89 (SQL Injection)
OWASP: A03:2021 – Injection
Endpoint: GET /artists.php
Parameter: artist
Server: Apache/2.4.41 (Ubuntu)

Description

User input on the artist parameter is not sanitized before being concatenated into SQL queries. This allows attackers to inject SQL control characters to bypass authentication and gain unauthorized access to the backend database.

Proof of Concept

GET /artists.php?artist=1' HTTP/1.1
Host: testphp.vulnweb.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)

Result: Application returned HTTP 200 OK with the full
artist list from the database — bypassing the query filter.

Result: Application returned HTTP 200 OK with full database records — bypassing input sanitization entirely.

✓ Remediation

  1. Use prepared statements / parameterized queries for all database interactions.
  2. Adopt an ORM (Eloquent, Prisma, Sequelize) with built-in sanitization.
  3. Apply the principle of least privilege to database service accounts.
Finding #2 — Stored Cross-Site Scripting (XSS)
HIGH
CVSS: 7.5
CWE: CWE-79
OWASP: A03:2021 – Injection
Endpoint: POST /profile/comments
Parameter: comment_body

Description

Comment input is stored in the database without HTML encoding. When other users view the profile, the malicious script executes in their browser, potentially stealing session cookies and hijacking user accounts.

Proof of Concept

Payload: <script>alert('XSS-Demo')</script>
Result : Script executed automatically in visitors' browsers.

✓ Remediation

  1. Apply context-aware HTML entity encoding on all user-supplied output.
  2. Enable a strict Content Security Policy (CSP).
  3. Sanitize input using libraries like DOMPurify.
Finding #3 — Missing CSRF Token Protection
HIGH
CVSS: 7.1
CWE: CWE-352
OWASP: A01:2021 – Broken Access Control
Endpoint: POST /api/v1/profile/update

Description

State-changing requests lack CSRF tokens, allowing attackers to forge requests on behalf of authenticated users via malicious third-party websites.

Proof of Concept

Crafted HTML form auto-submitted from attacker's site
→ Successfully updated victim's profile without consent.

✓ Remediation

  1. Implement anti-CSRF tokens (synchronizer token pattern).
  2. Use SameSite=Strict cookies for session tokens.
  3. Validate Origin and Referer headers on state-changing requests.
Finding #4 — Outdated JavaScript Libraries
MEDIUM
CVSS: 5.3
CWE: CWE-1104
OWASP: A06:2021 – Vulnerable & Outdated Components

Description

Frontend uses jQuery v1.12.4 (released 2016), which has multiple known CVEs including CVE-2020-11022 and CVE-2020-11023, allowing XSS via HTML manipulation.

✓ Remediation

  1. Upgrade to jQuery 3.7+ or migrate to vanilla JavaScript.
  2. Use Snyk or Dependabot for automated CVE monitoring.
  3. Remove unused dependencies to reduce attack surface.
Finding #5 — Missing HTTP Security Headers
LOW
CVSS: 3.1
OWASP: A05:2021 – Security Misconfiguration

Description

Response headers lack: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, HSTS, and Referrer-Policy. This exposes the application to clickjacking, MIME-sniffing, and protocol downgrade attacks.

✓ Remediation

  1. Add security headers on web server (Nginx/Apache).
  2. Enable HSTS with minimum 6-month max-age.
  3. Set CSP with restrictive default-src.
